# 松鼠文仓公开测试版云端与 AI 架构设计

## 1. 背景与目标

松鼠文仓 4.0 当前是原生 HTML、CSS 和 JavaScript 应用，数据保存在浏览器 `localStorage`，整理能力为本地逻辑。下一阶段面向中国大陆用户推出公开测试版，预计最多 500 名首批用户。

公开测试版必须提供：

- 邮箱验证码登录；
- 登录后的云端保存，同一账号在不同设备读取相同数据；
- 使用阿里云百炼通义千问完成真实 AI 整理；
- 从现有 `localStorage` 导入本机数据；
- 用户数据隔离、账号注销和数据删除；
- AI 用量限制、费用熔断、日志、告警和备份。

公开测试版只支持用户私有知识库。公开分享、多人协作、付费、团队空间和实时协同不在本期范围内。

## 2. 已确认约束

- 主要服务中国大陆用户。
- 阿里云账号为个人实名认证。
- 当前没有域名；购买域名、实名认证和 ICP 备案属于上线准备工作。
- 登录方式为邮箱验证码。
- AI 服务首选阿里云百炼通义千问，并通过内部模型适配接口调用。
- 目标规模为 500 名公开测试用户。
- 每位用户最多创建 10 个松鼠仓。
- 每位用户每天最多执行 3 次 AI 整理。
- 单次 AI 整理最多接收约 2 万个汉字。
- 同一用户同时最多运行 1 个 AI 任务。

## 3. 方案选择

### 3.1 选定方案：阿里云 Serverless

采用以下组件：

- ESA Pages：发布静态前端、配置 HTTPS 和自定义域名；
- API 网关：提供统一 `/api` 入口、基础限流和访问日志；
- 函数计算 FC：运行 Node.js API、认证逻辑和 AI Worker；
- RDS PostgreSQL：保存账号、会话、知识库、AI 任务和用量数据；
- MNS：排队执行 AI 任务，削峰并支持失败重试；
- 阿里云百炼：调用通义千问生成结构化文档；
- 邮件推送：发送邮箱验证码；
- OSS：保存用户上传的图标以及未来的导出文件；
- 日志服务与云监控：记录非正文日志、指标和告警。

该方案比 ECS 单体服务减少服务器补丁、数据库自建、进程守护和手动扩容工作；与海外 BaaS 相比，大陆访问和数据位置更可控。

### 3.2 服务边界

前端仅负责 UI、短期缓存和调用 HTTPS API。它不得持有数据库、百炼、邮件或 OSS 的长期密钥。

API 函数负责：

- 发送与验证邮箱验证码；
- 创建、刷新和撤销会话；
- 松鼠仓的读取、创建、保存、排序和删除；
- 本机数据导入；
- 创建和查询 AI 任务；
- 返回当日额度与可解释错误。

AI Worker 负责：

- 从数据库读取任务和用户材料；
- 调用内部模型适配接口；
- 校验模型结构化输出；
- 在事务内写回文档和松果映射；
- 记录 Token、模型、耗时、重试和费用估算。

## 4. 核心数据流

### 4.1 邮箱验证码登录

1. 用户提交规范化后的邮箱地址。
2. API 执行邮箱和 IP 限流，生成 6 位验证码。
3. 数据库只保存验证码哈希、有效期、尝试次数和发送状态。
4. 邮件推送服务发送验证码。
5. 用户提交验证码；验证成功后，验证码立即标记为已使用。
6. API 创建会话，并通过 `Secure`、`HttpOnly`、`SameSite=Lax` Cookie 返回会话令牌。

验证码 10 分钟过期；同一邮箱 60 秒内不得重复发送；每个邮箱每天最多发送 10 次，每个 IP 每天最多发送 30 次；连续错误 5 次后当前验证码失效。

会话默认有效 7 天，活跃使用时可续期，但单次登录最长不超过 30 天。数据库只保存会话令牌哈希。

### 4.2 云端保存

1. 用户修改仓库后，前端提交仓库 ID、完整状态和当前 `version`。
2. API 从会话取得 `user_id`，不采用前端传入的用户身份。
3. 更新必须同时匹配 `warehouse_id`、`user_id` 和 `version`。
4. 更新成功后数据库增加版本号并返回新版本。
5. 版本不匹配时返回冲突，前端提示刷新或保留本地副本，不静默覆盖云端数据。

云端数据是登录后的事实来源。`localStorage` 可以作为短期缓存，但不能在失败时伪装为已经完成云端保存。

### 4.3 AI 整理

1. 用户点击整理后，API 检查所有权、输入长度、当日额度和运行中任务数。
2. API 使用幂等键创建 `queued` 任务，并把任务 ID 写入 MNS。
3. Worker 将任务改为 `running`，读取最新仓库数据并调用百炼。
4. 模型响应必须通过 JSON Schema 和业务规则校验。
5. 校验通过后，在一个数据库事务中写入文档、章节映射、用量和完成状态。
6. 页面轮询任务状态；完成后刷新仓库，失败时显示可重试原因。

网络重试不得创建重复任务或重复扣减用户额度。百炼超时最多自动重试 2 次。模型响应无效或任务失败时不得覆盖原文档。

## 5. 数据模型

第一版采用关系表与仓库 JSON 快照的混合设计，复用 4.0 现有的按仓库隔离状态结构。

### 5.1 主要表

- `users`：邮箱、状态、创建时间、注销时间；
- `email_challenges`：邮箱、验证码哈希、过期时间、尝试次数、使用状态；
- `sessions`：用户 ID、令牌哈希、有效期、撤销时间；
- `warehouses`：用户 ID、名称、排序、版本号、完整仓库 `JSONB`、创建与更新时间；
- `ai_jobs`：用户 ID、仓库 ID、幂等键、状态、模型、输入摘要、输出、Token、费用估算、错误和时间戳；
- `usage_daily`：用户 ID、日期、AI 次数、输入与输出 Token；
- `uploaded_assets`：用户 ID、OSS 对象键、类型、大小和删除状态。

邮箱使用统一大小写和空白规则后建立唯一约束。AI 幂等键在用户范围内唯一。所有用户资源查询都必须包含 `user_id` 条件。

### 5.2 文件存储

自定义仓库图标上传到 OSS，数据库仅保存对象键和元数据。上传使用短期签名或由服务端中转，限制 MIME 类型、文件大小和像素尺寸。OSS Bucket 不允许公共写入；读取通过受控域名或短期签名完成。

## 6. 本机数据迁移

用户首次登录后，如果浏览器存在旧版 `localStorage` 数据：

1. 页面显示本机仓库数量和导入说明；
2. 只有用户明确确认后才上传；
3. 服务端验证状态版本、数量、大小和字段结构；
4. 每个导入批次使用幂等键，网络重试不产生重复仓库；
5. 云端已经有数据时，导入采用新增或明确的冲突处理，不自动覆盖；
6. 成功后云端成为事实来源，本地仅保留缓存；
7. 页面提供“暂不导入”，不阻止用户使用空账号。

## 7. 安全、隐私与内容处理

- 所有正式接口只使用 HTTPS。
- API 仅允许正式前端域名，并验证 `Origin`；Cookie 写操作使用 CSRF 防护。
- 数据库、百炼、邮件和 OSS 密钥保存在阿里云密钥管理或函数运行环境，禁止提交到 GitHub。
- 生产数据库不对公网开放，仅允许应用所在网络访问。
- 日志不得记录验证码、Cookie、密钥、松果正文或完整模型输入输出。
- 登录失败、验证码发送、额度拒绝和管理操作保留必要的安全审计记录。
- AI 整理前明确告知用户：所选材料会发送给模型服务处理。
- 上线前提供隐私政策、用户协议、账号注销和数据删除入口。
- 注销立即撤销会话，随后异步删除数据库资源和 OSS 对象；删除任务必须可重试和审计。

公开发布前应根据实际域名、托管区域和个人主体情况完成适用的 ICP 备案及其他合规手续。域名备案等待期可用于开发和小范围预发布，但不得把临时环境误宣传为正式长期服务。

## 8. 额度与费用保护

用户级限制：

- 最多 10 个松鼠仓；
- 每天最多 3 次 AI 整理；
- 同时最多 1 个运行中任务；
- 单次输入最多约 2 万个汉字。

系统级保护：

- 在 API 和队列 Worker 两处校验额度，数据库事务负责最终扣减；
- 设置函数并发、数据库连接数和队列消费并发；
- 设置全站每日 Token 或金额上限；达到上限后停止接受新任务，但不影响用户读取已有数据；
- 为百炼消费、邮件发送、函数错误率、数据库连接和队列积压设置告警；
- 管理员可以为指定测试账号调整额度，公开测试版不包含付费入口；
- 费用和额度配置不得硬编码在前端。

## 9. 错误处理与用户体验

前端新增以下状态和界面：

- 邮箱输入、验证码倒计时、发送失败和尝试过多；
- 云端保存中、保存成功、离线、版本冲突和保存失败；
- 首次登录的本机数据导入；
- AI 排队中、处理中、完成、可重试失败和额度耗尽；
- 当日剩余 AI 次数；
- 隐私同意、账号注销和数据删除确认。

错误响应使用稳定的机器错误码和安全的人类可读消息。服务端内部错误、SQL、堆栈和供应商原始响应不得直接暴露给用户。

## 10. 测试与验收

### 10.1 自动化测试

- 验证码过期、限流、错误次数和重复使用；
- 会话创建、续期、撤销和过期；
- 用户之间的仓库读取、更新、删除越权测试；
- 仓库版本冲突和幂等保存；
- 本机数据导入的校验、重试和重复导入；
- AI 额度、输入上限、并发限制和幂等任务；
- 百炼超时、重试、无效 JSON 和事务回滚；
- 注销后的会话失效与异步数据删除。

### 10.2 集成与人工验收

- 在开发、预发布和生产环境分别使用独立数据库与密钥；
- 使用桌面、手机和无痕浏览器验证邮箱登录及云端读取；
- 验证 4.0 本地数据导入、断网恢复和版本冲突提示；
- 验证 AI 处理中刷新页面仍能恢复任务状态；
- 验证达到用户额度和全站熔断后仍可读取与编辑已有数据；
- 验证日志和监控中不出现用户正文或敏感凭据；
- 对备份执行恢复演练，而不只检查备份任务成功状态。

## 11. 发布策略与监控

1. 开发环境使用测试数据库、测试发送域名和低额度百炼密钥。
2. 预发布环境邀请 5–10 人完成端到端验收。
3. 首批公开开放 50 人，观察至少一周。
4. 指标和费用稳定后逐步扩大至 500 人。

核心指标包括：注册成功率、首次建仓率、本机数据导入成功率、云端保存错误率、AI 成功率、平均排队和执行时间、日 Token 消耗、每日活跃用户及注销完成率。

前端保留上一稳定版本以便回滚。数据库迁移必须向前兼容或提供明确回滚脚本。提示词和模型变更先在预发布环境验证，再按小比例灰度，不直接覆盖所有任务。

## 12. 实施边界与顺序

该项目后续实施计划应拆成可独立验收的阶段：

1. 云端基础设施和环境隔离；
2. 后端项目、数据库迁移与认证；
3. 仓库云端 CRUD、版本控制和本机数据导入；
4. AI 异步任务、百炼适配、额度和费用保护；
5. 前端登录、保存、迁移和 AI 状态改造；
6. 安全、隐私、注销、监控和备份；
7. 预发布验收、灰度和公开测试。

每个阶段必须先完成自动化验证和预发布验收，再进入下一阶段。上线动作、购买云资源、购买域名、备案和启用付费服务需要由用户明确授权并在相应控制台完成。
