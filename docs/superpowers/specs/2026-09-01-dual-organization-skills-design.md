# 双模式整理 Skill 设计

## 目标

为松鼠文仓创建两个项目级 Skill，分别约束“保持当前分区”和“全部重新整理”的 AI 行为，使整理结果符合项目现有知识整理原则、双模式产品语义和数据契约。

## 存放方式

Skill 随项目版本管理，放在 `.agents/skills/`：

- `.agents/skills/merging-temporary-pinecones/`
- `.agents/skills/rebuilding-warehouse-document/`

项目级存放可以让 Skill 与产品规范、接口契约和实现同步演进，避免全局 Skill 与当前项目规则脱节。

## 共用权威资料

两个 Skill 均以以下项目文件为规范来源：

- `docs/fragmented-information-processing-principles.md`
- `docs/superpowers/specs/2026-08-30-pinecone-management-dual-organize-design.md`
- `contracts/ai-organize-request.schema.json`
- `contracts/ai-organize-result.schema.json`

`docs/松鼠文仓-产品实现链路与公开测试版方案.md` 已作为产品背景材料查阅，但其中同时包含新旧方案，不作为 Skill 的运行时权威引用。发生冲突时，以 2026-08-30 双模式设计和当前 JSON Schema 为准。

## Skill 一：保持当前分区

名称为 `merging-temporary-pinecones`。

### 使用场景

当整理模式为 `merge`，需要把暂存栏新增松果并入当前结构化文档，同时保留用户已有文档结构、人工修改和旧松果引用时使用。

### 输入

- 当前仓库名称；
- 当前契约可表达的文档完整上下文；
- 当前章节与旧松果引用；
- 仅限状态为 `temp` 的新增松果。

### 行为

- 先把每颗新增松果拆成知识单元并判断信息类型；
- 优先匹配最合适的现有章节；
- 只向匹配章节追加新内容，不改写原有字段；
- 没有合理归属时才创建新章节；
- 合并重复新增信息，但保留重要限定、来源和不确定性；
- 不引入原材料中没有的新知识。

### 硬约束

- 当前文档标量和旧数组元素保持不变；现有要点与旧引用作为不可变前缀，仅允许尾部追加新内容；
- 契约外批注由调用方另行原样保留，不进入模型读写范围；
- 生成前检查旧前缀能否满足结果 Schema；由于请求与结果限制不对称，旧章节超过 20 个要点、无法形成至少一个章节或无法满足章节引用要求时，返回契约兼容错误，不得删改旧内容绕过；
- 每颗暂存松果在章节级映射中恰好出现一次；跨主题内容按主导主题选择唯一章节；
- 不得删除、移动或重新归类旧松果；
- 整理失败时不得产生部分应用结果。

## Skill 二：全部重新整理

名称为 `rebuilding-warehouse-document`。

### 使用场景

当整理模式为 `rebuild`，需要使用仓库全部原始松果重新识别主题、建立结构并整体替换当前文档时使用。

### 输入

- 当前仓库名称；
- 仓库中的全部原始松果；
- 当前文档只作为即将被替换的状态，不作为必须保留的内容约束。

### 行为

- 从全部松果提取知识单元并区分事实、观点、方法、例子、术语、问题和结论；
- 先识别主题和子主题，再按阅读路径聚类；
- 根据材料类型建立完整文档骨架；
- 合并重复信息，降低表达噪声，保留知识含量；
- 保留来源痕迹并标记冲突、残缺或待验证内容；
- 不按粘贴顺序或来源顺序机械分章。

### 硬约束

- 输出可以整体替换旧标题、章节、摘要、要点和人工修改；
- 输入的全部松果 ID 必须在章节级映射中恰好出现一次；跨主题内容按主导主题选择唯一章节；
- 每个章节至少对应一颗松果；
- 章节 ID 唯一；
- 不得编造事实或擅自扩写成新文章；
- 模型只返回候选文档；调用方验证后派生松果架和位置并原子替换；整理失败时保留原版本。

## Skill 结构

每个 Skill 包含：

- `SKILL.md`：触发条件、流程、硬约束、输出检查和反模式；
- `agents/openai.yaml`：在 Codex 界面中的名称、描述和默认提示；
- `references/`：该模式需要的精简规范与可复用检查清单。

不复制整份项目文档。`SKILL.md` 保留执行所需的核心规则，并链接项目内权威资料供深入核对。

## 验证方法

两个 Skill 分别执行红—绿验证：

1. 不加载 Skill，让独立代理处理包含冲突、重复、旧人工修改和引用关系的压力场景，记录基线偏差；
2. 创建 Skill；
3. 加载 Skill 后用相同场景复测；
4. 检查是否满足该模式的内容质量和 ID 映射硬约束；
5. 运行 `quick_validate.py` 检查 Skill 结构；
6. 两个 Skill 均通过后运行项目现有检查。
